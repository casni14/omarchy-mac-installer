## Validation

The host used Xcode's Apple Swift 6.4, target arm64-apple-macosx27.3.0. The Docker builder is ARM64 Ubuntu 26.04 with its base image digest pinned in the Dockerfile. XcodeBuildMCP was unavailable, so Xcode's bundled Swift tools were used.

The engine was independently repacked twice with identical bytes, passed archive mode checks and preserved the authenticated native runtime. Inspection of the rebuilt archive confirmed the J616s device/chip table, boot selector, host Wi-Fi logic and patched C2 firmware collector were included.

`test/all` passed, including 77 engine recipe tests, 408 overlay tests, 301 catalog tests, 36 release tests, packaging/identity shell checks and board selector tests. The overlay suite skipped one platform-dependent test. Debug Swift tests ran 833 cases and release ran 818, each with one skipped and zero failures, plus four Swift Testing cases in each configuration. The standalone Recovery checks passed and its signed template passed inventory validation. Compiler output was moved out of Documents after file-provider Finder metadata caused an initial signing failure.

Read-only btrfs, ext4 and FAT filesystem checks passed. Pacman's package dependency database passed after the image transaction. The Limine entry references the expected J616s platform UKI. The produced metadata/payload passed the engine's normal preflight with Apple restore and target Wi-Fi input mocked. The installer's native Swift verifier accepted the sealed catalog, local trust root and release descriptor and admitted J616s only.

The app uses ad-hoc signatures, an exact helper code-hash requirement and the existing ad-hoc helper provisioning path, which pins the client and restore decoder hashes when the user authorizes registration. No Developer ID certificate was available. This candidate has no Apple notarization.
